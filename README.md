# 有下文 · Afterword

让每一次收藏，都有下文。

Save it. See where it leads.

有下文（英文名 Afterword）是 Android 个人研究资料库：收藏网页、文字、图片和 PDF，在本地保存原始资料，按个人关注点生成观点卡片与主题综述，再按授权开展外部研究。V3 加入今日推荐、个人背景、结构化阅读与可恢复的 Android 后台分析，保留归档、回收站和来源链约束。

项目原名 Readlater；内部 package、applicationId 与本地数据路径继续保留 `readlater` 标识，以支持已安装版本和既有数据兼容。更名范围与本次验证见 [更名记录](docs/AFTERWORD_RENAME.md)。

长尾狐图标已接入导航、功能按钮、空状态与操作反馈，Android 桌面、启动及通知图标使用同一品牌轮廓。资源生成方法和接入验证见 [长尾狐 App 接入记录](docs/branding/APP_INTEGRATION.md)。

## 开发协作

开发流程、分支与提交、测试和发布规范见 [CONTRIBUTING.md](CONTRIBUTING.md)；AI 协作规则见 [AGENTS.md](AGENTS.md)。首次获取仓库运行 `flutter pub get --enforce-lockfile`、`bash tool/setup-dev.sh`，随后用 `bash tool/check.sh full` 验证。代码托管于 [JikeStardy/afterword](https://github.com/JikeStardy/afterword)，主分支为 `main`；AI 可提交功能分支，合并和推送需用户授权。

## GitHub 自动构建

推送 `main`、向 `main` 提交 PR 或手动运行 `Android` workflow，会执行完整检查并构建 Android arm64 APK。登录 GitHub 后进入 [Actions](https://github.com/JikeStardy/afterword/actions/workflows/android.yml)，打开成功运行，在构建摘要的「Android 安装包下载」或 Artifacts 下载 `Afterword-<版本>-android-arm64.apk`，无需解压；SHA-256 校验文件、签名和构建信息各自提供独立下载项，保留 14 天。

主分支可从仓库 Secret 恢复现有个人测试签名；PR 不读取签名密钥。没有固定签名时产物明确标为临时测试包，可能不能覆盖旧版本。配置和验收说明见 [GitHub 构建](docs/GITHUB_BUILD.md)。此流程不自动创建 Release 或发布到应用商店。

## 开发环境

- Flutter **3.47.5** / Dart **3.13.4**（依赖版本见 `pubspec.lock`）
- Android SDK 36、JDK 21；Android 首期。iOS/macOS 工程已保留，平台能力仍需对应阶段补齐和验收。
- Node.js 用于可选的本地集成测试服务和品牌资源生成，不是 App 运行依赖。

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64
flutter run -d <android-device-id>
```

当前整合版本为 **0.3.1+4**，面向 Android arm64，最低 Android 7.0（API 24），targetSdk 36。以上命令生成 APK，默认位置为 `build/app/outputs/flutter-apk/app-release.apk`。当前 release 构建使用 debug 密钥签名，供个人测试安装，不适用于应用商店正式发行。全部需求与已整合功能见 [统一交付清单](docs/INTEGRATED_DELIVERY.md)。

## 今日、阅读与个人知识

- 默认进入「今日」，每天最多五项本地推荐，展示理由，可处理、跳过、延后及反馈；手动刷新补充候选。
- 待判断／阅读中／已处理／搁置与归档分开；已处理资料仍可用于研究，浏览次数不代表完成。
- 正文保留标题、列表、代码、表格和图片上下文，支持位置恢复、高亮批注、PDF 页笔记及正文历史版本；在「设置 → 外观与阅读 → 阅读字号」统一调整原文、分析与笔记字号，立即保存。
- 主题可维护背景、目标、限制、判断和未解决问题，选择资料与背景范围；笔记修改会标记相关结论过时。
- 检索包括原文、笔记、批注、分析及研究成果；资料和研究支持带来源的 Markdown 导出。
- RSS 支持跳过、隐藏已处理、批量处理、暂停和退订，未收藏内容不自动进入研究。

## 后台分析与通知

提交先保存到本地并入队，Android 前台服务继续处理。长文、PDF 和外部研究记录阶段进度；系统中断后下次打开恢复，取消的任务不会自动恢复。配置变化及持续失败需要手动重试。供应商已接收但结果未保存的请求可能重发并重复计费，研究预算不会重置。

运行进度、任务结果、每日汇总、研究提醒分别设置。每日默认本地 20:00 左右，允许系统延迟，无候选不通知；汇总只读取本地资料，不调用模型和搜索。拒绝通知权限不会阻止分析。后台与锁屏表现仍受系统和厂商省电限制影响；设备验证状态见 [统一交付清单](docs/INTEGRATED_DELIVERY.md)。

备份包含业务数据，排除运行队列、中间进度、待发送通知和密钥；恢复后的未完成工作需要手动重试。

## 资料管理

- 阅读页、资料列表和研究页采用统一阅读层级，可在设置切换「阅读刊物」「紧凑研究工具」「数字杂志」三种外观。阅读页分为原文、分析、笔记，已有分析时默认打开分析；证据按需展开并可跳转原文。
- 资料页支持搜索、使用中／已归档／回收站范围，以及未读／已分析／异常筛选。长按可批量管理，五个底部页面保留当前浏览状态。
- **归档保留原文、附件和历史成果，但排除新的分析、关联、综述、兴趣推断与研究输入。** 依赖该资料的旧成果也不能间接进入新推理；旧成果仍可回看，来源状态会显示。取消归档后才重新参与处理。
- 删除先进入回收站，默认保留 **7 天**，可在设置改为 **3 天**。恢复保留原归档状态；归档资料从回收站恢复后仍需取消归档才成为使用中资料。永久删除、清空回收站及缩短保留期需要确认。
- 应用启动、回到前台时检查到期资料；缩短保留期确认后立即清理按新期限已到期的资料。不会承诺应用关闭时后台准时清理。永久删除清除该资料及其分析、相关详细日志和无引用受管附件；独立保存的历史主题／研究成果与来源标识保留以供追溯。
- 资料状态改变会停止受影响的后续处理并丢弃迟到结果；已经发送给服务商的请求无法撤回。

## 开发者日志

在「设置 → 开发者」查看任务状态、步骤时间线、模型调用、HTTP 状态、请求 ID 和服务商实际返回的 usage；未返回的用量显示为未提供。失败资料或研究可跳转到相关任务，日志支持导出与确认后清空。

「App 事件与诊断包」另提供当前进程内的临时 DEBUG、事件筛选和不含模型正文的诊断快照，可预览后导出或主动上传电脑。接收端配置与令牌可保存，重启恢复 INFO；不会自动启用模型完整交互记录。使用方法见 [诊断说明](docs/diagnostics.md)。

详细请求／响应记录默认关闭，需要主动打开调试开关。日志过滤 API Key、认证头、Cookie 等敏感信息，图片只保留元数据，不记录 Base64 图片内容；详细日志仍可能包含原文与模型回答，导出前应检查内容。普通任务记录保留 **30 天**，详细请求／响应保留 **7 天**，单次请求或响应最多 **256 KiB** 并标明截断；逻辑日志容量上限 **50 MiB**，超过时清理最早任务，SQLite 文件另有结构开销。资料备份不包含独立诊断日志。

## 首次使用

1. 在「设置」填写兼容 Chat Completions 的服务地址、模型名及自己的 API Key。地址可以是服务的 `/v1` 基址，或完整 `/chat/completions` 地址。
   云端模型及搜索地址必须使用 HTTPS；HTTP 仅支持本机或局域网服务。
2. 图片/PDF 分析另外填写支持图片输入的多模态模型名。模型 Key 存在系统安全存储中，原文和研究数据存在设备应用目录。
3. 若要外部研究，在搜索设置填写自己的 **Tavily API Key**。模型 Key 与搜索 Key 分别配置；不配置搜索也能收藏和做库内分析。
4. 从浏览器/微信公众号使用系统分享进入 App，或在资料页添加链接、文字、图片和 PDF。
5. RSS 新条目只供浏览；点选收藏后才分析。没有模型配置时，原文仍保存，界面提示待配置。
6. 阅读观点卡片，按需创建主题、生成综述或确认研究建议。开启持续追踪需要确认主题范围、频率和调用上限。

## 授权与数据行为

- 库内总结、关联与主题更新可自动执行，不会自动调用搜索服务。
- 外部研究须单次确认或已有的主题追踪授权。修改主题问题会撤销旧追踪授权。
- 每次研究的调用上限合计搜索和模型请求，默认 6 次，可选 2–30 次；这不是货币金额或无限月度额度。
- 追踪默认 24 小时，可选 1–720 小时；应用运行时周期检查，打开/恢复时补查，错过多次只补一轮。不会依赖云端常驻任务，也不保证手机关闭时准时执行。
- 原文、附件、观点卡片、主题和研究记录都在本地。模型推理会把所需内容发送给配置的服务；搜索会把研究查询发送给搜索服务。
- ZIP 备份使用数据版本 4，兼容导入版本 1–4，拒绝未知版本；不含 API Key。备份包含会话、分段摘要、知识提案与修订、归档资料及未到期回收站资料；不保存临时渲染图片或运行授权。恢复中的对话标记为中断，不自动重发结果不确定的请求。备份保留原删除时间；导入前排除已到期资料，不重新计时。恢复替换资料库，需要界面确认；追踪授权恢复后暂停，调试关闭，当前诊断日志清空。原始附件与来源关系随备份一起恢复。旧版来源链不明的成果保留可读，但不能自动作为新推理输入。
- 恢复保留当前设备的模型与搜索服务配置，避免备份更改密钥发送目标；换机需重新填写服务配置与密钥。备份上限 256 MB、解压后 512 MB、最多 10,000 个条目，超限会明确提示。
- 建议自行定期导出备份；卸载 App 可能删除其私有目录，尚无多设备同步。

## 内容边界

- 网页重点处理微信公众号 `#js_content` 与普通博客正文。遇到登录、风控或无法提取内容时保存链接并明确提示，不能保证所有微信公众号文章都能自动获取。
- 前台手动添加或系统分享的新微信链接，直接抓取失败后会自动打开可见网页；正文加载稳定后自动保存，遇到验证可在页面中正常完成。页面加载完成后的自动检测最多 60 秒，之后仍可手动保存；取消后不反复弹窗，后台任务和 RSS 不自动打开页面。原文页仍可选择「打开页面保存」或「粘贴正文」，已有提取内容也可「补充正文」。正文标明保存方式，保留来源和旧版本，图片下载失败可单独补图。页面保存仅支持 Android HTTPS 微信链接；不同文章或无法核实身份的短链/长链转换会拒绝覆盖。原有记录见 [微信收藏回退记录](docs/WECHAT_RECOVERY.md)，本次调整与验证见 [阅读与导入修复](docs/READING_IMPORT_FIXES.md)。
- 保存主要图片供离线阅读，单篇最多 30 张；下载失败会明确提示。网页请求上限 5 MB，图片下载上限 10 MB。
- 导入支持 PNG/JPEG/WebP/GIF/PDF，单文件上限 50 MB；Android PDF 通过系统渲染器按每批最多 4 页送多模态分析，目前支持 100 页以内。原始文件单独保留。
- 长文本和 PDF 使用中立分段摘要与层次合并，摘要按原文版本、范围和指纹缓存；笔记或偏好不会进入原文摘要。PDF 每批仅发送当前页，历史资料只在最终分析中关联。原文和原附件完整保留。
- 单篇“问这篇资料”、主题“围绕主题讨论”和研究页“问知识库”提供持久化多轮交流。全文按问题检索窗口，模型可自动补读原文、PDF 页及图片；显示已读范围、调用次数、来源版本和证据。视觉观察明确未经精确文字核验，GIF 仅读取首帧。
- 每问默认 5 次模型调用，可设 1–20 次；视觉和失败重试均累计，最后一次必须回答。每次序列化文字默认最多 24000 UTF-16 字符，可设 8000–64000，这是字符预算而非 token 数。文字硬上限 256 KiB，每请求最多 4 张归一化图片、每张最多 1 MiB，整体 HTTP 体最多 8 MiB；90 秒覆盖整个请求，超时或取消中止对应请求。
- 交互、后台各一条模型执行通道，同一会话仅一个在途轮次。单资料完成后合并为后台增量知识建议，不同步重生成所有主题。新来源及对话形成提案，审阅差异、编辑并确认后才更新知识页；旧自动综述继续独立可读。知识修订可回看及恢复，来源失效的历史不进入新推理。
- 主题自动发现基于多条收藏中出现的兴趣方向；关注不等于赞同。明确偏好可编辑，自动推断的偏好也可修改。
- 视频、Mac 交付、同步与实践执行不属于此 Android 首期交付。

## 本地设备集成测试

测试使用受控服务验证 HTTP 协议与完整业务链，不声称验证了任何付费模型的真实回答质量。

```sh
# 终端一：仅监听本机
node tool/fixture_server.mjs

# 终端二：启动 Android 模拟器或连接测试设备后
adb reverse tcp:18765 tcp:18765
flutter test integration_test/device_flow_test.dart -d <android-device-id>
```

集成测试创建单独的临时资料库，通过真实设备 SQLite、HTTP、文件与 PDF 渲染接口运行。测试设备上会写入仅供夹具使用的模型/搜索 Key，不应在存有个人生产配置的设备上运行测试。单元测试不需要真实 API Key。

知识对话夹具在测试设备内启动本地 HTTP 服务，无需 Node.js 或端口反向转发；覆盖超长资料缓存复用、尾部证据、知识确认、原生 PDF/图片和备份恢复。`--no-uninstall` 保留测试截图供提取，请同样使用专用测试设备：

```sh
flutter test integration_test/knowledge_dialogue_device_test.dart -d <android-test-device-id> --no-uninstall
```

## 结构

- `lib/core`：领域数据、SQLite/附件/备份、资料生命周期、独立诊断日志和应用用例。
- `lib/services`：网页与RSS解析、云端模型、受预算约束的研究循环。
- `lib/platform` 与 `android`：系统分享、PDF渲染、文件查看与通知。
- `lib/ui`：今日、资料、RSS、研究与设置界面。
- `test` / `integration_test`：行为测试、平台契约与设备流程。
- `docs/superpowers/specs`：需求基线。
- `docs/superpowers/plans`：实现顺序和接口约定。
