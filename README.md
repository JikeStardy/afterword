# Readlater

Android 个人研究资料库：收藏网页、文字、图片和 PDF，在本地保存原始资料，按个人关注点生成观点卡片与主题综述，再按授权开展外部研究。V2（0.2.0+2）加入归档、回收站和开发者日志，并统一为暖白、深绿的阅读与列表界面。

## 开发环境

- Flutter **3.47.5** / Dart **3.13.4**（依赖版本见 `pubspec.lock`）
- Android SDK 36、JDK 21；Android 首期。iOS/macOS 工程已保留，平台能力仍需对应阶段补齐和验收。
- Node.js 仅用于启动可选的本地集成测试服务，不是 App 运行依赖。

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64
flutter run -d <android-device-id>
```

本轮交付目标为 **0.2.0+2**，面向 Android arm64，最低 Android 7.0（API 24），targetSdk 36。以上命令生成 APK，默认位置为 `build/app/outputs/flutter-apk/app-release.apk`。当前 release 构建使用 debug 密钥签名，供个人测试安装，不适用于应用商店正式发行。

V2 的交付状态、全量测试、静态分析、Android 构建和设备验证以 [V2 交付说明](docs/V2_DELIVERY.md) 中的证据为准。分项实现与审查记录位于 [docs/v2](docs/v2)，[原验收映射](docs/ACCEPTANCE.md) 和 [原实现状态](docs/IMPLEMENTATION_STATUS.md) 保留为 V1 历史记录，不能代替 V2 验证。

## V2 阅读与资料管理

- 阅读页采用用户确认的 A 方案，资料列表和日志页采用 B 方案，共用暖白 `#FAF8F3`、深绿 `#476B4F`、无衬线字体和 12dp 控件圆角。阅读页分为原文、分析、笔记，已有分析时默认打开分析。
- 资料页支持搜索、使用中／已归档／回收站范围，以及未读／已分析／异常筛选。长按可批量管理，四个底部页面保留当前浏览状态。
- **归档保留原文、附件和历史成果，但排除新的分析、关联、综述、兴趣推断与研究输入。** 依赖该资料的旧成果也不能间接进入新推理；旧成果仍可回看，来源状态会显示。取消归档后才重新参与处理。
- 删除先进入回收站，默认保留 **7 天**，可在设置改为 **3 天**。恢复保留原归档状态；归档资料从回收站恢复后仍需取消归档才成为使用中资料。永久删除、清空回收站及缩短保留期需要确认。
- 应用启动、回到前台时检查到期资料；缩短保留期确认后立即清理按新期限已到期的资料。不会承诺应用关闭时后台准时清理。永久删除清除该资料及其分析、相关详细日志和无引用受管附件；独立保存的历史主题／研究成果与来源标识保留以供追溯。
- 资料状态改变会停止受影响的后续处理并丢弃迟到结果；已经发送给服务商的请求无法撤回。

## 开发者日志

在「设置 → 开发者」查看任务状态、步骤时间线、模型调用、HTTP 状态、请求 ID 和服务商实际返回的 usage；未返回的用量显示为未提供。失败资料或研究可跳转到相关任务，日志支持导出与确认后清空。

详细请求／响应记录默认关闭，需要主动打开调试开关。日志过滤 API Key、认证头、Cookie 等敏感信息，图片只保留元数据，不记录 Base64 图片内容；详细日志仍可能包含原文与模型回答，导出前应检查内容。普通任务记录保留 **30 天**，详细请求／响应保留 **7 天**，单次请求或响应最多 **256 KiB** 并标明截断；逻辑日志容量上限 **50 MiB**，超过时清理最早任务，SQLite 文件另有结构开销。资料备份不包含独立诊断日志。

## 首次使用

1. 在「设置」填写兼容 Chat Completions 的服务地址、模型名及自己的 API Key。地址可以是服务的 `/v1` 基址，或完整 `/chat/completions` 地址。
   云端模型及搜索地址必须使用 HTTPS；HTTP 仅支持本机或局域网服务。
2. 图片/PDF 分析另外填写支持图片输入的多模态模型名。模型 Key 存在系统安全存储中，原文和研究数据存在设备应用目录。
3. 若要外部研究，在搜索设置填写自己的 **Tavily API Key**。模型 Key 与搜索 Key 分别配置；不配置搜索也能收藏和做库内分析。
4. 从浏览器/微信公众号使用系统分享进入 App，或在资料页添加链接、文字、图片和 PDF。
5. RSS 新条目只供浏览；点选收藏后才分析。没有模型配置时，原文仍保存，界面提示待配置。
6. 阅读观点卡片，按需创建主题、生成综述或确认研究建议。开启持续追踪需要确认主题范围、频率和调用上限。

## 授权与数据行为

- 库内总结、关联与主题更新可自动执行，不会自动调用搜索服务。
- 外部研究须单次确认或已有的主题追踪授权。修改主题问题会撤销旧追踪授权。
- 每次研究的调用上限合计搜索和模型请求，默认 6 次，可选 2–30 次；这不是货币金额或无限月度额度。
- 追踪默认 24 小时，可选 1–720 小时；应用运行时周期检查，打开/恢复时补查，错过多次只补一轮。不会依赖云端常驻任务，也不保证手机关闭时准时执行。
- 原文、附件、观点卡片、主题和研究记录都在本地。模型推理会把所需内容发送给配置的服务；搜索会把研究查询发送给搜索服务。
- ZIP 备份使用数据版本 2，兼容导入版本 1 和 2，拒绝未知版本；不含 API Key。备份包含归档资料与未到期回收站资料，保留原删除时间；导入前排除已到期资料，不重新计时。恢复替换资料库，需要界面确认；追踪授权恢复后暂停，调试关闭，当前诊断日志清空。原始附件与来源关系随备份一起恢复。旧版来源链不明的成果保留可读，但不能自动作为新推理输入。
- 恢复保留当前设备的模型与搜索服务配置，避免备份更改密钥发送目标；换机需重新填写服务配置与密钥。备份上限 256 MB、解压后 512 MB、最多 10,000 个条目，超限会明确提示。
- 建议自行定期导出备份；卸载 App 可能删除其私有目录，尚无多设备同步。

## 内容边界

- 网页重点处理微信公众号 `#js_content` 与普通博客正文。遇到登录、风控或无法提取内容时保存链接并明确提示，不能保证所有微信公众号文章都能自动获取。
- 保存主要图片供离线阅读，单篇最多 30 张；下载失败会明确提示。网页请求上限 5 MB，图片下载上限 10 MB。
- 导入支持 PNG/JPEG/WebP/GIF/PDF，单文件上限 50 MB；Android PDF 通过系统渲染器按每批最多 4 页送多模态分析，目前支持 100 页以内。原始文件单独保留。
- 长文本分段分析，再合并结果。历史资料关联采用本地文本相似度和阅读信号，不需要额外的向量服务。
- 主题自动发现基于多条收藏中出现的兴趣方向；关注不等于赞同。明确偏好可编辑，自动推断的偏好也可修改。
- 视频、Mac 交付、同步与实践执行不属于此 Android 首期交付。

## 本地设备集成测试

测试使用受控服务验证 HTTP 协议与完整业务链，不声称验证了任何付费模型的真实回答质量。

```sh
# 终端一：仅监听本机
node tool/fixture_server.mjs

# 终端二：启动 Android 模拟器或连接测试设备后
adb reverse tcp:18765 tcp:18765
flutter test integration_test/device_flow_test.dart -d <android-device-id>
```

集成测试创建单独的临时资料库，通过真实设备 SQLite、HTTP、文件与 PDF 渲染接口运行。测试设备上会写入仅供夹具使用的模型/搜索 Key，不应在存有个人生产配置的设备上运行测试。单元测试不需要真实 API Key。

## 结构

- `lib/core`：领域数据、SQLite/附件/备份、资料生命周期、独立诊断日志和应用用例。
- `lib/services`：网页与RSS解析、云端模型、受预算约束的研究循环。
- `lib/platform` 与 `android`：系统分享、PDF渲染、文件查看与通知。
- `lib/ui`：资料、RSS、研究与设置界面。
- `test` / `integration_test`：行为测试、平台契约与设备流程。
- `docs/superpowers/specs`：需求基线。
- `docs/superpowers/plans`：实现顺序和接口约定。
