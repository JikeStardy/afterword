# 分析输入裁剪修复

2026-10-02，分支 `fix/analysis-payload-budget`。

## 问题与变化

原 `itemPayload` 的裁剪上限作用于每个段落，而不是整篇资料；分析还同时发送正文与原文块，历史摘要没有上限。受控测试中，一篇历史资料发送 104,403 字符的原文和摘要，一篇主题来源发送 100,390 字符的原文块。

- 当前资料仅发送结构化原文块，保留全文、块 ID 和版本；长文继续由控制器分段。
- 历史资料原文节选与已有摘要合计最多 4000 字符。已有分析时，摘要和原文各最多 2000 字符。
- 主题每条来源的原文块合计最多 6000 字符。
- 分段合并仅发送一份中间文本，仍须原样复用已收集的原文证据。
- 被裁剪的来源标明 `contentTruncated`；本地原文与历史成果不被修改。

## 验证

Flutter 3.47.5 / Dart 3.13.4，沿用锁定依赖。

- 修复前：`flutter test --no-pub test/analysis_payload_test.dart` 的四项回归测试均失败，分别复现重复正文、历史裁剪失效、重复中间文本与主题裁剪失效。
- 修复后：输入预算、模型服务、证据合并、控制器、后台恢复与生命周期的针对性测试共 96 项通过。
- `bash tool/check.sh full`：格式检查、静态分析、13 个 Git 钩子场景及全部 307 项单元／Widget 测试通过。
- 独立 code-reviewer 审查通过；`git diff --check` 通过。

## 边界

以上字符预算只涵盖原文块和单资料分析的历史摘要，不包含笔记、批注、偏好、主题完整分析成果、分段合并成果或图片。没有增加整个请求的 token 上限，也未调整 90 秒网络等待、自动主题调度、PDF 每批历史关联或手动重试策略。
