# Readlater 剩余需求与执行清单

更新日期：2026-09-26。初始核对基线：`feat/personal-insights-background` / `fdf4655`，V3 `0.3.0+3`。RL-01 最新实现见 `feat/wechat-capture-recovery` 与下方执行记录。

当前 Android 整合版本为 `0.3.1+4`，统一功能范围、各分支整合关系和最新验证见 [统一交付清单](INTEGRATED_DELIVERY.md)。下列未完成需求仍保留，整合安装包不等于关闭全部设备矩阵和后续平台需求。

依据用户“分优先级，逐个完成”的要求整理，作为后续执行入口。以下是当前工作排序，不改写已确认需求，也不表示已验收。后续能力的产品细节及新增技术依赖在对应任务中确定。

## 优先级与执行顺序

- **P0：Android 日常使用闭环。** 解决主要收藏来源、运行可靠性和真实服务可用性。
- **P1：知识积累的实际价值。** 用真实资料检验已有功能，并按观察到的问题迭代。
- **P2：后续平台。** Android 闭环稳定后开展 Mac；iPhone 保留为待排期。
- **P3：后续能力。** 视频、实践指导、具体内容产出先明确需求，再安排开发。

## RL-01：微信公众号成功收藏与失败回退

**目标与依据：** 满足 V1 CAP-01/02/03、AC-01：正文、主要图片、来源可保存并离线回看，失败可识别、可补充。历史四条真实样本未取得正文，不据此推断所有文章均失败。WebView 是候选方案，尚未证明实际可用。

- [ ] 用可正常打开的真实文章记录 HTTP 获取结果及失败分类。
- [ ] 对验证或动态加载问题，验证“可见 WebView → 用户正常操作 → 同一页面提取正文”的可行性。
- [x] 实现可见页面保存与原条目粘贴正文，保留通用图片/PDF 导入；真实站点可行性仍待设备验证，手动导入不等于自动收藏验收通过。
- [x] 分开记录正文与图片结果，补图失败不丢弃已取得正文；行为测试覆盖。
- [x] 实现取消、导航变化、超时、重复保存、错误页面及归档/来源链保护；核心测试与独立审查完成，原生动态行为仍待设备验证。
- [ ] 真机核对正文首尾、主要图片与来源，验证重开和离线阅读。

**完成条件：** 真实成功和失败链路均有设备证据；验证页不会被当成正文，剩余不支持情况明确列出。静态 HTML 测试、WebView API 可用或手动兜底均不能单独关闭该项。

**依赖：** 可访问样本、Android 测试设备；新增依赖须单独说明并按协作规范处理。

## RL-02：Android 后台、恢复与通知设备验收

**目标：** 已实现的后台能力在实际设备上符合 V3 约定，发现的缺陷有修复与回归证据。

- [ ] 重新检查设备与模拟器条件；历史启动失败不作为当前环境结论。
- [ ] 长文/PDF 提交后切后台、锁屏，核对进度、结果和资料保存。
- [ ] 检查系统中断恢复、取消不恢复、迟到结果拒绝、预算不重置和可能重复费用提示。
- [ ] 检查通知允许/拒绝、完成/失败、分组、冷启动定位及分享复制取消。
- [ ] 检查每日调度、时区变化、去重、无候选不通知、digestOnly 零网络。
- [ ] 检查服务时限、唤醒锁释放、Doze 与目标真机厂商省电条件。
- [ ] 补齐计划中的 API 24/33/35/36 检查，记录实际设备与系统版本。
- [ ] 运行 V3 设备集成流程，覆盖 SQLite、迁移/恢复和来源关系；失败先复现再修复。

**完成条件：** [设备专项流程](V3_DEVICE_TESTS.md)及上述矩阵有本轮结果，失败项完成修复复测。部分设备通过只记部分完成，不用 APK 编译、mock 或旧版记录替代。

**依赖：** 可启动模拟器或专用测试设备；测试不得覆盖个人生产配置。

## RL-03：真实模型与搜索供应商联调

**目标：** 实际选定的服务能完成核心链路，错误、授权与预算边界符合约定。

- [ ] 明确服务地址、文本/多模态模型和搜索配置，密钥仅通过现有安全设置配置。
- [ ] 实测文字、长文、图片、PDF 分析，核对证据定位和个人背景输入。
- [ ] 实测多轮研究、调用上限、取消和授权撤销。
- [ ] 检查认证失败、限流、断网及格式不兼容时的保存、错误提示和重试。
- [ ] 核对实际 usage 与日志脱敏，记录可读且来源可核查的结果样本。

**完成条件：** 所选服务有实际成功与失败记录，兼容范围明确到服务和模型。一个供应商通过不代表所有兼容接口通过；测试夹具不作为真实服务证据。

**依赖：** 用户选定服务、可用凭据和实际调用费用边界。密钥不写入文档、源码或夹具。

## RL-04：个人知识积累与持续追踪效果

**目标：** 验证收藏是否转化为有来源、可修订的认识，而非仅增加摘要。

- [ ] 选择真实主题，明确背景、目标、约束、待解决问题及观察周期。
- [ ] 检查真实资料的新增信息、相似观点、冲突关联和原文证据。
- [ ] 修改笔记及个人判断，评价过时标记与成果更新是否有用。
- [ ] 评价今日推荐、观点反馈和综述，保存具体有用/无用案例。
- [ ] 在明确授权内观察持续追踪，检查有效变化、重复内容与通知噪声。
- [ ] 将问题拆为独立缺陷或需求，修复后用同一案例复核。

**完成条件：** 有用户真实反馈和可回看案例，说明认识如何积累及剩余问题。开始时明确观察周期与质量标准，不擅定固定天数或准确率；流程跑通不等于效果验收通过。

**依赖：** 真实资料、反馈和 RL-03 的可用服务；积累案例无需等待全部跨版本设备验收。

## 逐项完成与记录

状态：**待开始 → 进行中 → 待验收 → 完成**；缺少外部条件记为**阻塞**，写清已完成部分与解除条件。

1. 核对最新代码、工作区和条件，明确本次范围，不重复开发已有功能。
2. 在功能分支实施或验收；缺陷先复现并补行为测试，保护无关改动。
3. 代码变更执行针对性测试、`full` 和独立审查；平台变更追加 `android` 与设备流程。
4. 记录提交、实际检查、证据及限制；达到完成条件后再关闭该项并推进下一项。
5. 合并 main、上传代码、发布仍需明确指令，不随需求完成自动执行。
