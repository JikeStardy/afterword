# 阅读与导入修复

日期：2026-09-28。分支：`fix/reading-import`，基线 `685020c`。本次不升级版本、不新增依赖、不合并或推送。

## 行为

- 字号调整移至「设置 → 外观与阅读 → 阅读字号」，范围 85%–160%，立即保存并应用于所有资料的原文、分析、笔记与正文历史。阅读页不再显示常驻滑杆，系统文字缩放仍生效。旧单篇字号字段保留以兼容旧数据，全局设置缺失时为 100%，不再从单篇字段取值。
- 正文解析按页面顺序保留 `div`、`section`、行内混排和语义块，避免丢段或父子重复，保留作者刻意重复的文字。优先明确的 `articleBody` 与微信公众号正文。腾讯云文章采用实际观察到的 `.rno-markdown` 容器，排除站点广告和相关推荐。
- 没有明确正文容器、且仅获得标题与元描述摘要时报告提取不足。明确正文容器中的有效短文不会因与元描述相同而被拒绝。这些判断不能证明任意网站内容完整，界面改为「已保存提取内容」，保留补充正文入口。更新旧内容仍保留原版本、来源和批注失效提示。
- 前台手动链接／系统分享的新微信资料启用一次可见网页回退。HTTP 成功时直接保存；失败时从同一导入任务继续读取 WebView，不另行取消其他队列任务。后台、RSS、旧任务重试与取消后不会自动反复弹窗。
- WebView 在页面完成加载、正文可见且文本／标题／图片信息稳定 2 秒后自动保存；最终提取与签名复验在同一次 JS 执行完成，内容变化继续等待。自动阶段最多 60 秒，之后保留手动保存。导航、错误、关闭和超时使迟到回调失效；来源身份、HTTPS、大小限制保持生效。

## 复现与审查

先编写行为回归，确认旧实现漏掉混排正文、误取摘要、无自动回退和补全入口，再修改实现。独立代码与 Kotlin 审查发现「完整短文等于元描述」和「稳定探测后正文变化」两项问题，均增加复现测试并修复，复审通过。

截图标题匹配的腾讯云页面为 https://cloud.tencent.com/developer/news/1116925 。本机直接 HTTP 返回脚本挑战；浏览器正常打开后观察到真实正文容器（72 个段落和 5 个 figure），据此建立脱敏结构夹具。此证据不等于设备 HTTP 在所有网络上都能取到全文。
