# 微信公众号收藏与失败回退

日期：2026-09-26。任务：RL-01。分支：`feat/wechat-capture-recovery`。

## 已实现行为

- 保留 HTTP 收藏快路径。网页没有正文或明确提取失败时，在原文页显示恢复操作；已有正文的模型配置/分析错误不被当作抓取失败。
- Android HTTPS 微信文章支持打开可见的系统 WebView。用户正常完成站点交互、确认正文后点击保存；提取同一页面的 HTML，交由既有解析器处理。取消不修改资料。
- 原条目支持粘贴正文和可选标题；保留原 ID、来源链接、备注与附件，含 URL 的文本仍按正文保存，不重抓、不新增条目。
- 标记 `bodyOrigin` 为页面保存或手动粘贴，旧数据默认空值；正文历史也保留该标记。字段为数据 v3 的向后兼容可选字段，不改变 schema 版本或依赖。
- 正文先持久保存，图片及分析沿用本地队列。图片失败保留正文并提示补图；没有模型配置时正文仍可阅读。正文替换保留历史、标记原批注锚点失效及相关成果过时。
- 保存前检查归档/回收站、资料身份、生命周期、版本与原正文。旧任务标记为已被替代，不能通过任务重试覆盖新正文；补图中断后重试不会重新 HTTP 抓取正文。

## 页面与来源边界

原生和 Dart 两侧均限制 HTTPS `mp.weixin.qq.com`、无 URL 凭据、默认 443 端口。WebView 禁止文件/content 访问、混合内容、弹窗及下载；证书错误终止，不注入可供网页调用的原生 JS bridge，不导出 Cookie，不记录完整 HTML。

导航、提取超时和迟到结果使用独立令牌校验。退出或宿主 Activity 销毁会取消提取并释放 WebView；初始化异常不会遗留占用状态。页面 HTML 上限 5 MiB，原生和 Dart 都验证；手动正文上限 5 MiB，标题最多 500 字符。

为避免把文章 B 的正文写到文章 A 的来源下，保存时校验文章身份：短链比较 `/s/<标识>`，长链比较 `__biz/mid/idx`，其余地址保守比较去 fragment 后的完整地址。**无法核实同一文章的短链到长链转换会拒绝保存**，提示回到原文或另行收藏；可使用粘贴正文兜底。不能据此承诺所有微信验证和重定向都可用。

图片仍由既有 HTTP 下载器单独下载，不携带 WebView 会话 Cookie；因此页面可读不代表图片都能成功离线保存。系统浏览器或微信中的登录态也不会自动导入本应用。

## 设备验收步骤（未执行）

2. 打开页面，按站点要求正常验证。正文出现后保存，核对标题、首尾段、主要图片、来源链接和保存方式；断网、重开后再次核对。
3. 让图片下载失败，确认正文可读且有警告；补图只下载图片，不重抓或覆盖正文。
4. 验证页尚未出现正文时保存应被拒绝；取消、系统返回及 Activity 重建不产生空正文或重复资料。
5. 从原文章跳到另一篇文章后保存应被拒绝；提取时导航、超时后重试不采纳旧结果。
6. 在失败条目粘贴含 URL 的正文，确认原 ID/链接不变、没有额外抓取，且标明手动来源。已有正文被替换后历史与失效锚点可回看。
7. 补图阶段取消后从任务页重试，确认正文不重抓；补正文后旧失败任务不得恢复覆盖。归档/回收站期间不得补写正文。
8. 在小屏、1.8 倍文字、键盘展开、断网和通知权限拒绝情况下检查主要操作。运行项目既有 `device_flow_test.dart` 与相关设备回归。
