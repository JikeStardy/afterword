# Readlater 本地 Git 与开发规范实施计划

依据本次用户批准的完整计划：仅本地 Git；个人与 AI 协作；提交前快速检查；AI 自动提交功能分支，合并 main 由用户明确发起。本次不改功能、接口、数据结构或依赖版本。

## Task 1：建立已交付版本基线

完善忽略规则和换行属性，保留 Gradle Wrapper、锁文件、文档与精选截图；审核首次暂存清单，运行当前全量测试。初始化 main，首次提交已交付 0.2.0，并建立带说明的 v0.2.0 标签；不构造历史。创建 chore/git-development-standards 分支。

## Task 2：独立整理格式

仅格式化已发现的两个测试文件，验证既有全量测试，独立提交，不改变业务或测试含义。

## Task 3：规范与检查工具

增加中文 CONTRIBUTING、AGENTS、编辑器配置和 README 入口。提供 check.sh fast/full/android、幂等 setup-dev.sh、本地 pre-commit 钩子。SDK 经 PATH 或 FLUTTER_BIN 定位，不硬编码机器路径；不得自动解析依赖、格式化、暂存或 stash。

钩子审查暂存空白和禁止文件，文档提交跳过 SDK；源码输入存在未暂存或未跟踪文件时阻止源码提交。保留已有 hooksPath 与默认钩子，不更改全局配置。

## Task 4：测试、审查与交付

先以临时真实 Git 仓库测试缺失能力，再实现工具；验证成功提交、格式／分析失败、禁止文件、部分暂存、未跟踪源码、环境缺失、安装重复／冲突及失败不改文件或 index。

执行真实 full；独立审查整段变更；在临时本地克隆准备依赖、安装钩子、运行 android，验证源码可独立测试和构建。记录命令与实际结果。无远端、main 与 v0.2.0 保持基线、规范分支干净且未合并。

## 审查重点

暂存状态与工作区不一致导致误放行、强制加入忽略文件、配置覆盖已有钩子、外层 Git 环境污染临时测试仓库、SDK 解析与脚本引号、检查是否意外改动源码或依赖。
