# 新版 Readlater 实施约定

实现用户确认的 A 阅读页 + B 资料列表和日志页，共用暖白 #FAF8F3、深绿 #476B4F、无衬线字体、线性图标与12dp控件圆角。参考 outputs/readlater-designs/统一视觉规范.md。Android 优先，不新增依赖，不引入账号、同步或视频。

## 任务 1：模型与备份（data agent）

拥有 lib/core/models.dart、lib/core/store.dart、test/models_test.dart、test/store_test.dart、新增 test/lifecycle_store_test.dart。
- LibraryItem: nullable DateTime archivedAt, trashedAt; getters isArchived,isTrashed,isActive（两者均空）。删除归档资料保留 archivedAt。
- Analysis, Topic, ResearchRun: nullable List<String> inputItemIds，null=旧数据来源不明，[]=无资料输入；与 sourceIds 分开。序列化保留 null。
- AppSettings: int trashRetentionDays=7，仅3/7；bool debugModelLogging=false；List<String> confirmedInterests=[]（用户对推断兴趣的明确确认/编辑，不随推断重算丢失）。
- AppData version2，兼容1/2，拒绝未知版本；旧输出保留可读，不猜来源链。
- LocalStore.cleanUnusedAssets(AppData data): 仅删除受管且无引用附件；只在无附件写入任务时调用，失败可下次重试，不清理任意路径。历史引用不重写。
- 备份包含已归档和未到期回收站，删除时间不重置；恢复在提交前移除到期回收站资料，清空其 RSS savedItemId，并不遗失来源链。恢复保留设备模型配置且关闭调试，旧版迁移测试。无需在 store 实现归档动作（controller拥有）。

## 任务 2：独立诊断日志与网络仪表（diagnostics agent）

拥有新 lib/core/diagnostics.dart、lib/services/intelligence_service.dart、新 test/diagnostics_test.dart 和 test/intelligence_test.dart。
- DiagnosticStore extends ChangeNotifier: 构造 DiagnosticStore(String path)，独立SQLite文件；普通任务30天、详细交互7天、总50MB（逻辑容量受限及空间回收），单请求/响应256KiB截断提示；时钟/容量可注入测试。
- 供controller使用的稳定接口：bool debugEnabled; String? lastError; Future<T> runTask<T>({required String type, required String title, String? entityId, List<String> inputItemIds=const [], bool Function()? allowed, required Future<T> Function() body}); Future<T> step<T>(String label, Future<T> Function() body); void failCurrent(String message); void addInputIds(Iterable<String> ids); void prune(); void clear(); void purgeItemPayloads(Set<String> ids); Uint8List exportLogs({String? taskId}); void close(). 任务和步骤用 Zone 关联并发，防止交叉日志；嵌套runTask独立记录parentId。
- UI 查询接口尽早回复父代理。必须有任务类别/状态/开始结束时间、entityId、步骤、每次调用请求响应/模型/状态码/请求id/实际usage（缺失为未提供）；任务中断恢复。可读错误、任务状态不可把失败标成功。
- DiagnosticScope.ensureAllowed() 静态：读取当前zone allowed，false抛取消异常；网络发送前、收到响应后、解析/后续循环前检查。保持 IntelligenceService 现有公共override签名，别破坏旧fake。
- 请求完整内容只在debugEnabled当次开启时记录；不持久化key、认证头、cookie、data:image base64；只保留附件metadata。清理所有嵌套敏感键和实际已知凭据（也包括错误/响应中回显）；usage等普通元数据可常存。
- 默认无调试只记录调用元数据；非2xx也先限量读取响应以供排错，格式错误/超时/过大均记录；日志故障不使业务失败但lastError可見。
- 研究过滤已知排除URL：可通过 DiagnosticScope 暴露当前 excludedUrls（由controller context传入；如接口需要请先协调）。不要改变无zone情况下既有行为。

## 任务 3：统一UI与管理（UI agent）

拥有 lib/ui/*（包含新developer_page.dart）、新增 test/v2_ui_test.dart，现有UI测试可因交互变化合理更新；不要改controller/models/服务。
- 资料页紧凑列表，搜索、使用中/已归档/回收站范围、全部/未读/已分析/异常筛选，单项更多与长按批量归档/取消归档/删除/恢复/永久删除。永久删除和清空需确认，删除入回收站不必额外确认。空列表与无结果分开，状态保持。
- controller方法约定 Future<void> archiveItems(Iterable<String> ids), unarchiveItems, trashItems, restoreItems, purgeItems；Future<void> setTrashRetentionDays(int days), setDebugModelLogging(bool enabled)。LibraryItem getters如任务1。来源标签controller.sourceLabel(String id)。
- 阅读页原文/分析/笔记tab，已有分析默认分析，正文17sp/1.7行距、主要内容开放排版，附件独立展开。归档/回收站可读但禁新分析/研究。发起分析建议research增加originItemId:item.id。
- 日志入口设置→开发者，任务类别/状态筛选，任务详情可视时间线、请求/响应/用量及导出、清空、调试开关和保留说明；从资料或研究失败可定位相关entityId任务。controller.diagnostics 为 DiagnosticStore。等待diagnostics代理接口后对接。
- 所有页一致主题、图标、控件；保留4底部导航，用IndexedStack保留页面状态；通知/错误不重叠。
- 设置保存不能丢新字段（AppSettings.fromJson旧settings.toJson再改，或显式传入）；回收站3/7天可配置，缩短提示到期效果。
- 320/390/430宽、大字体溢出测试，管理、tabs、日志关键widget测试；真实图片不依赖网络。

## 任务 4：业务整合（主代理）

controller生命周期动作及自动到期清理；关联、综述、研究previousReport、自动兴趣全链路排除归档/回收站及依赖它们的旧输出，未知来源的旧输出只读；仍有效资料可用原文重算。
应用自己记录完整输入祖先ID（含偏好贡献），不能信任模型sourceIds。采用资料状态revision及每步/每次调用前后检查；变更后丢迟到结果、停止后续调用，不宣称撤回已发送请求。原文抓取/附件导入并发安全。
RSS与重复收藏显示原归档/回收站状态不复活；支持打开现有项目。自动主题没有有效支持暂停。备份与恢复清理先于任务执行；附件清理避开在途写入。
按任务接入保存/提取/模型/写入步骤与失败；持久化普通错误不泄密；debug开关设备本地，永久删除擦除相关详细日志。

## 任务 5：验收与交付

先失败再通过的行为测试：生命周期、来源链间接污染、在途取消、备份迁移、debug脱敏/失败/容量、UI操作。静态分析、全量测试、Android构建、模拟器或设备集成与屏幕核对。独立code-reviewer/Flutter审核修复实质问题。更新版本0.2.0+2、交付APK/源码/说明，保留用户项目修改。真实外部模型未配置不阻止夹具验证，但不冒充真实供应商验收。
