# 知识对话实施计划

日期：2026-10-02。用户已批准实施。分支：`feat/knowledge-dialogue`。

## 交付范围

原文完整保存，全文按问题检索窗口，模型可在有限调用中补读文字、PDF 页和图片。分析形成可复用的中立分段摘要。对话持久化，提供单篇、主题及知识库入口；新来源和对话形成待确认知识提案，经差异审阅后写入独立的知识修订，保留旧自动综述。

每问默认 5 次模型调用（设置 1–20），包括视觉及重试，发送前计数，最后一次仅回答；恢复不自动重发不确定请求。每次总文字上下文默认 24000 UTF-16 字符（设置 8000–64000），这是字符预算而非 token 数。序列化文字硬上限 256 KiB，归一化单张图片最多 1 MiB、每请求最多 4 张、整个 HTTP 体最多 8 MiB。HTTP 90 秒覆盖发送至接收完成，超时和取消中止该请求。

交互和后台各一条执行通道，同一会话仅一个在途轮次，原生媒体处理串行。上下文按任务绑定，取消单个任务不影响另一个通道。

证据仅可引用本轮实际发送的窗口，记录来源版本、块 ID、UTF-16 偏移和指纹。视觉记录绑定原文件 SHA256 与页码，明确未经精确文字核验。归档、删除、修订或配置变化后拒绝后续读取及迟到提交，历史可阅读但失效成果不得再次进入推理。

AppData 升级 v4，兼容 v1–v4；RuntimeState 升级 v2，兼容 v1–v2，未知版本拒绝。新任务 v2，旧 v1 检查点维持旧恢复路径。备份含会话、分段摘要、提案及修订，不含运行授权、凭据、临时媒体及 base64；恢复中的轮次标为中断。

接受提案时同步检查基础修订与全部输入指纹，先保存分离副本再发布到内存，失败不留半成品；重复接受幂等。恢复历史内容创建新修订。用户编辑标记 humanEdited，不提升证据可信度。

## 顺序与分工

1. 数据模型与迁移：models / store，新模型及备份测试。
2. 全文检索与协议：retrieval / conversation_service，尾部窗口、精确证据、受限补读及预算测试。
3. 执行基础：Zone 任务上下文、双通道、HTTP 整体超时与中止、预算。
4. 业务控制器：会话迭代、来源守卫、知识提案事务及后台增量建议。
5. 长源处理：中立分段缓存、层次合并、PDF 单批排除历史、原生图像归一化。
6. 界面：三个入口、历史、状态与取消、知识差异确认、修订恢复及设置。
7. 整合验证：针对行为测试、full 检查、Android 构建与设备夹具、独立代码审查；修复后再提交功能分支。

不引入新依赖，不上传、发布或合并 main。保护已有未跟踪研究文档。

## 验收重点

- 超长单段后半部可检索，原文不截断，重复分析复用缓存。
- 对话范围、所有实际依赖及引用可追溯；摘要不能冒充原文。
- 预算穷尽、失败重试、进程恢复、配置变化、资料变更、取消均有行为测试。
- 双通道并发与单通道取消隔离；事务失败无内存半提交。
- v1–v4 迁移与备份恢复，视觉路径变化仍保留原文件身份。
- 320px、1.8 字体、输入键盘、长回答和重开会话可用。
- 夹具通过不表示真实模型供应商已通过，最终报告明确实测边界。
