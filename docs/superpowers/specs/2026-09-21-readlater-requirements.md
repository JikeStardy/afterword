## 2. 产品定位、用户与成功标准

### 2.1 产品定位〔已确认〕

Readlater 是面向个人自用的资料收藏与研究 App。它统一接收主动收藏的内容和 RSS 信息，保存原始资料，使用 LLM／Agent 提供个性化分析、资料关联、外部研究与持续追踪，帮助用户把收藏逐渐转化为有依据、可积累的认识。

产品首先服务“稍后处理”，其中第一阶段的处理以研究为主。阅读总结与综述是获取认识的方式，原始资料库为分析提供长期积累。当资料和理解足够丰富后，再扩展到实践指导与具体产出。

### 2.2 目标用户与优先级〔已确认〕

- 第一版面向个人自用，无需账号和运营后台；公开发布与分发方案不在本次需求范围内。
- 日常主要使用 Android，第一期优先覆盖 Android。
- 第一优先级：每次阅读能够留下有来源的认识，并积累为有用的主题综述。
- 基础要求：资料能可靠收藏、保存、离线阅读，并支撑后续回看和关联。
- 进一步价值：App 主动发现值得研究的信息，推进问题，减少用户亲自搜索与整理的工作。

优先级不等于删除功能：多轮外部研究、持续追踪、多模态分析、兴趣自动发现均属于已确认的第一期功能范围，可以按开发顺序分批交付，但不能默认为远期功能。

### 2.3 成功标准〔已确认〕

用户能够从收藏和阅读中留下有来源、可回顾的认识，并看到这些认识逐渐形成围绕个人关注问题的主题综述。验证所需的使用时长尚未确定。

本文不设未经讨论的收藏数量、准确率、延迟、留存率或费用指标。第一版验收以真实使用流程和可观察的成果为依据。

## 3. 阶段范围〔已确认〕

| 阶段 | 范围与约束 |
| --- | --- |
| 第一期 | Android 优先；网页、文字、图片、PDF 收藏；RSS；本地保存与备份恢复；个人模型 Key；个性化分析；观点卡片；主题综述；多轮研究；持续追踪。 |
| 跨端要求 | 从第一期设计时考虑 iPhone、Mac 的开发复用；不预先指定框架，也不要求第一期同时交付所有平台。 |
| 第二期 | Mac 客户端。iPhone 的具体交付期次仍待后续排期，不因考虑复用而默认属于第一期或第二期。 |
| 后续发展 | 视频支持、实践指导、具体内容产出。资料积累后的实践或产出，不作为第一期默认处理结果。 |
| 暂不包含 | 多设备同步、账号系统、运营后台、公开发布所需的运营能力。 |

“暂不同步”不取消备份与恢复。“允许云端模型分析”不代表把资料库托管到产品服务器。“持续追踪”不要求手机离线时仍由云端代为运行。

## 4. 核心概念与用户成果〔已确认〕

| 概念 | 产品含义 |
| --- | --- |
| 原始资料 | 用户保存的网页正文、主要图片、文字记录、图片、PDF 及其来源。原始资料与模型生成的内容分别保留。 |
| 观点卡片 | 默认的分析成果，用于呈现一个认识及其依据、适用条件等信息；不能仅凭名称把它缩减成标题摘要。 |
| 研究主题 | 用户持续关注的方向与问题；允许与自由收藏共存，不要求每次收藏时先归类。 |
| 主题综述 | 围绕研究问题综合多条资料形成的认识，反映相关观点、分歧和未解决的问题，随积累更新。 |
| 研究建议 | 阅读后可以采纳的下一步查证、比较或延伸问题；建议本身不等于外部研究已经执行。 |
| 单次外部研究 | 经用户确认后，Agent 围绕目标开展多轮搜索、阅读、比较与查证。 |
| 持续追踪 | 用户按主题授权后，在频率和用量边界内反复研究、发现变化并更新认识的任务。 |
| 偏好 | 用户明确表达的关注点与分析要求，以及从使用行为推断出的兴趣。明确反馈具有更高优先级。 |

第一期“可执行动作”主要表现为研究建议、一次研究任务或持续追踪任务。通用待办管理、日历和项目执行系统未被确认为第一期需求。

## 5. 功能需求〔已确认〕

### 5.1 平台与使用方式

| 编号 | 需求 |
| --- | --- |
| PLT-01 | 第一期开发表现和验收优先面向 Android 手机。 |
| PLT-02 | 架构考虑后续 iPhone、Mac 的复用；Mac 在第二期，具体复用框架另行设计。 |
| PLT-03 | 按个人自用设计，不需要账号和运营后台。 |

### 5.2 主动收藏与原始保存

| 编号 | 需求 |
| --- | --- |
| CAP-01 | 支持从 Android 系统分享入口接收网页链接，微信公众号文章和普通博客是主要验收来源。 |
| CAP-02 | 网页保存可离线阅读的正文、主要图片、来源以及分析结果；不要求保留原网页完整布局。 |
| CAP-03 | 网页提取失败时保留链接，明确标记失败状态，便于重试或手动补充。失败不能表现成正文已完整保存。 |
| CAP-04 | 支持直接输入文字、粘贴摘录和补充收藏备注；这些内容可用于表达收藏原因、疑问和关注点。 |
| CAP-05 | 支持图片和 PDF 资料入库及多模态模型分析，不把它们仅定义为待后续分析的附件。 |
| CAP-06 | 主动分享的内容保存后自动进入总结、初步分析和已有资料关联流程；模型未配置或任务失败时不能宣称分析已完成。 |

### 5.3 RSS 接收与筛选

| 编号 | 需求 |
| --- | --- |
| RSS-01 | 支持 RSS 订阅、接收和浏览信息。 |
| RSS-02 | RSS 条目由用户挑选后才进入分析流程，未选中的条目不因到达订阅源而自动调用模型分析。 |
| RSS-03 | 选中的 RSS 内容进入与主动收藏一致的保存、总结、关联和研究流程。 |

本期不把“根据兴趣自动挑选 RSS 并分析全部候选”作为默认行为。必要的订阅拉取与已确认内容的获取，不等同于另行开展外部研究。

### 5.4 默认分析与知识积累

| 编号 | 需求 |
| --- | --- |
| ANA-01 | 对入选内容做个性化总结和初步分析，同时关联已有收藏，形成对单条内容和相关历史资料的理解。 |
| ANA-02 | 默认输出观点卡片，围绕观点、依据和适用条件等组织认识。 |
| ANA-03 | 关联分析需要服务于认识积累，例如识别新增信息、相似观点和观点冲突，避免只是多篇摘要的并列展示。 |
| ANA-04 | 分析后可提出进一步研究建议，用户阅读后决定是否启动外部研究。 |
| TOP-01 | 支持自由收藏和长期研究主题并存。 |
| TOP-02 | 用户可以明确指定持续关注的主题，或按需请求主题综述。 |
| TOP-03 | App 必须能够根据兴趣和资料积累发现值得关注的主题，并在库内自主生成或更新综述；不要求每次更新都另行确认。 |
| TOP-04 | 主题综述围绕研究问题综合已有资料，反映当前认识、分歧和未知，保留来源依据。 |

### 5.5 个性化与兴趣理解

| 编号 | 需求 |
| --- | --- |
| PER-01 | 用户明确反馈优先于行为推断，包括关注主题、内容是否有用、关注点和分析要求。 |
| PER-02 | 收藏、阅读、重复查看、研究建议采纳等行为可以辅助推断兴趣与分析偏好。 |
| PER-03 | 推断出的兴趣和偏好可由用户查看、修改，并用于后续分析。 |
| PER-04 | 区分“关注该主题”和“认同该观点”；不能仅因打开或收藏某篇文章，就认定用户赞同其中结论。 |

### 5.6 多轮外部研究

| 编号 | 需求 |
| --- | --- |
| RES-01 | 外部搜索、查证和延伸研究需要用户确认；默认分析不能以关联资料为名自行跨入外部研究。 |
| RES-02 | 获得确认后，Agent 能围绕目标多轮搜索、比较、发现缺口并继续查证，而不限定为一次搜索。 |
| RES-03 | 研究具有明确目标和用量边界，结束后提供有来源的结论、尚未解决的问题与后续研究建议。 |
| RES-04 | 研究成果用于更新用户对主题的认识，并保存在本地，供后续阅读和关联。 |

### 5.7 持续追踪与通知

| 编号 | 需求 |
| --- | --- |
| TRK-01 | 用户可以按主题开启持续追踪，一次授权后允许 App 在该主题范围内周期性自主开展外部研究。 |
| TRK-02 | 持续追踪有研究频率和用量上限，允许用户随时暂停。具体频率、单位与默认数值后续确定。 |
| TRK-03 | 扩大已授权研究范围时，再次获取用户确认。 |
| TRK-04 | 任务以手机本地执行为主，允许因离线、未打开 App 或执行条件不足而延后；下次打开时补查遗漏的信息。 |
| TRK-05 | 展示最近执行时间和待执行状态，不把期望频率显示成已经执行的事实。 |
| TRK-06 | 只在重要新发现、结论变化或需要用户决策时通知，不要求每轮运行都推送例行状态。 |

### 5.8 本地数据、模型与恢复

| 编号 | 需求 |
| --- | --- |
| DAT-01 | 原始资料、笔记、分析结果、研究成果保存在本地，形成可长期积累的原始资料库。 |
| DAT-02 | 第一期不同步，不依赖产品账号或产品服务器保存完整资料库。 |
| DAT-03 | 支持手动导出、备份和恢复；恢复后原始资料与研究成果应保持可用。 |
| DAT-04 | 已保存的网页正文和主要图片可离线阅读；离线阅读能力不等于云端分析也可以离线运行。 |
| MOD-01 | 用户使用自己的 API Key，配置模型服务地址、文本模型与多模态模型，由自己的模型账号承担调用。 |
| MOD-02 | 允许把分析所需内容发送给云端 LLM；明确区分本地存储与云端推理，不承诺全部内容永不离开设备。 |

## 6. 自动化与授权边界〔已确认〕

| 行为 | 是否可自动执行 | 触发与限制 |
| --- | --- | --- |
| 获取用户分享的网页、保存正文 | 可以 | 用户主动分享或明确收藏，遵守原始资料保存规则。 |
| 拉取 RSS 条目供浏览 | 可以 | 基于用户添加的订阅，不自动把全部条目送去模型分析。 |
| 主动分享内容的总结与库内关联 | 可以 | 用户已配置模型；分析所需内容可以发送到其配置的云端服务。 |
| RSS 内容的总结与库内关联 | 挑选后可以 | 未经挑选的 RSS 条目不自动分析。 |
| 兴趣推断与库内主题综述 | 可以 | 明确反馈优先，偏好可查看和修改；建议自动成果说明触发原因（PER-05，待确认）。 |
| 普通外部搜索与延伸研究 | 需要确认 | 展示研究建议、目标与用量边界，确认后可多轮推进。 |
| 已授权主题的持续外部研究 | 可以 | 遵守主题范围、研究频率、用量上限及暂停状态。 |
| 扩大持续研究范围 | 需要再次确认 | 已有主题授权不等于任意方向的无限研究权限。 |
| 实践操作或具体内容产出 | 后续能力 | 第一版不把研究授权视为执行实际业务操作的授权。 |

云端模型推理和外部资料搜索是不同的动作：默认分析允许调用云端模型，但不能因此自动获得联网搜索新资料的权限。后台执行允许延后，也不扩大用量或研究范围。

## 7. 典型用户流程〔已确认〕

### 7.1 分享一篇博客，形成可积累的认识

1. 用户从浏览器或微信公众号分享文章到 Readlater。
2. App 保存正文、主要图片和来源，显示保存结果；失败时保留链接与失败状态。
3. 保存成功后，结合关注点做总结和初步分析，并关联已有收藏。
4. 默认输出观点卡片及后续研究建议。
5. 用户阅读，提供反馈；如果主题值得持续关注，可指定为重点主题并获取综述。
6. 用户确认研究建议后，Agent 开展多轮外部研究，返回有来源的结论与未知问题。
7. 相关成果保存在本地，成为后续分析与主题更新的依据。

### 7.2 浏览 RSS，选择值得处理的内容

1. 用户添加订阅并浏览新条目。
2. 未挑选的条目保持可浏览状态，不自动调用模型分析。
3. 用户挑选需要处理的内容，进入保存和分析流程。
4. 分析结果与主动收藏内容共同参与主题研究。

### 7.3 围绕主题持续追踪

1. 用户为主题开启持续追踪，确认研究范围、频率和用量上限。
2. App 在允许的执行条件下自主研究并更新认识。
3. 手机离线或未运行造成的任务延后，在下次打开时补查，并显示真实执行状态。
4. 出现重要新发现或结论变化时通知用户；无重要变化时保持安静。
5. 用户可暂停追踪；扩大研究方向需要再次确认。

### 7.4 贯穿示例：个人知识管理

研究主题：**个人知识管理——怎样把收藏的资料变成实际可用的认识？**

用户收藏一篇讲读书笔记方法的博客。默认分析提炼其核心方法，结合用户明确关注的“适用条件”进行说明，再关联库内关于摘录、卡片笔记或复习方法的资料，形成带依据的观点卡片。如果资料存在分歧，综述呈现不同主张和待查证的问题。

App 可以提出“查证某种笔记方法在不同使用场景中的效果”等研究建议，但先等待用户确认。确认后，Agent 多轮搜索并比较资料，更新主题认识；如果用户进一步授权持续追踪，App 才按该主题持续开展外部研究。

以上文章和研究发现仅用于说明流程，不构成对任何具体方法有效性的事实判断。

## 8. 建议的验收细化〔尚未作为独立产品决定确认〕

以下条目用于指导后续设计讨论和测试设计。它们是对可靠性、来源可追溯性与恢复能力的建议，不能与第 5 节已确认需求混为一谈。

| 编号 | 建议 | 原因 |
| --- | --- | --- |
| SUG-01 | 观点卡片和综述可跳转到具体依据；缺乏支持时明确标为推断或待查证，不编造来源。 | 使“有来源的认识”能够被实际核查。 |
| SUG-02 | 保存、解析、分析、研究分别呈现状态；模型失败不影响已保存原始资料，支持重试。 | 避免把采集成功和分析成功混淆。 |
| SUG-03 | 预算耗尽、任务中断或网络失败时保留已有进展，并解释未完成原因。 | 让 Agent 的自动执行可理解、可恢复。 |
| SUG-04 | 备份包含成果与来源之间的关系，恢复后校验这些关系；密钥是否包含在备份中另行设计。 | 避免文件存在但研究依据丢失。 |
| SUG-05 | 区分用户笔记、原文陈述与模型生成结论，并保留更新线索。 | 避免原始事实与生成内容混在一起。 |
| SUG-06 | 当库内暂无相关资料时明确说明，不制造关联；明确反馈与行为推断冲突时能看出采用了哪个依据。 | 使冷启动和个性化行为可验证。 |
| SUG-07 | 建议明确暂停时已在执行的任务如何停止、保留进展和结算用量；具体方式留待技术设计。 | 补充在途任务的处理规则；暂停后不启动新轮次已由 TRK-02 和 AC-20 约束。 |
| SUG-08 | 对长期未运行的追踪合并补查，避免无意义地逐个重放全部错过的定时任务。 | 补查遗漏信息，同时尊重用量上限。 |
| PER-05 | 自动生成或更新重点主题成果时说明触发原因；保留原编号便于引用，此条为建议待确认。 | 帮助用户理解自主分析与自身兴趣之间的联系。 |

## 9. 验收场景

### 9.1 已确认需求的功能验收

下表描述预期验收结果，不代表已经执行测试或实现功能。

| 场景 | 关联需求 | 输入／前提 | 预期行为与通过结果 |
| --- | --- | --- | --- |
| AC-01 微信文章收藏 | CAP-01、CAP-02 | 分享一篇可正常获取的微信公众号文章。 | 进入资料库，正文、主要图片与来源可查看；断网后仍可阅读已保存内容。 |
| AC-02 普通博客收藏 | CAP-01、CAP-02 | 分享一篇普通博客文章。 | 保存可阅读正文与主要图片，内容可参与分析，不以完整网页布局保真为通过条件。 |
| AC-03 提取失败 | CAP-03 | 分享一条无法提取正文的链接。 | 链接保留，失败状态明确；用户能够识别需要重试或补充，不能显示为完整保存。 |
| AC-04 文字记录 | CAP-04、ANA-01 | 输入文字、粘贴摘录并写入关注点。 | 内容和备注得到保存，可作为分析输入；关注点能影响分析。 |
| AC-05 图片分析 | CAP-05、MOD-01 | 保存图片并配置支持该输入的模型。 | 图片保存在本地，多模态模型对其内容产生可阅读的分析结果。 |
| AC-06 PDF 分析 | CAP-05、MOD-01 | 保存 PDF 并配置可用的多模态处理方案。 | PDF 可作为原始资料保留，内容能进入模型分析及关联流程；不以单纯保存附件替代分析能力。 |
| AC-07 RSS 未选中 | RSS-01、RSS-02 | 订阅到达若干新条目，用户未挑选。 | 条目可以浏览，未自动触发内容分析。 |
| AC-08 RSS 选中 | RSS-03 | 用户选中某个 RSS 条目。 | 进入保存、总结和库内关联流程，后续可用于主题研究。 |
| AC-09 默认成果 | CAP-06、ANA-01、ANA-02 | 主动分享内容，模型已配置且可用。 | 自动总结和分析，默认形成观点卡片，包含认识及来源依据，而非仅留下未处理链接。 |
| AC-10 关联既有资料 | ANA-03 | 库内已有相关或相互冲突的内容，再加入新资料。 | 分析体现新增信息、关联或分歧，用户能理解新资料对已有认识的影响。 |
| AC-11 自由收藏与主题 | TOP-01、TOP-02 | 保存未归类资料，再明确关注某研究问题。 | 不强制先建主题才能收藏；用户能指定重点主题并请求综述。 |
| AC-12 自主主题更新 | TOP-03、TOP-04 | 累积相关资料及兴趣信号。 | App 能发现值得关注的主题并生成或更新库内综述；该过程仅使用库内资料，不自动开展外部搜索。触发原因说明按 PER-05 作为待确认的补充验收。 |
| AC-13 偏好可纠正 | PER-01、PER-02、PER-03 | 存在推断偏好，用户查看并修改。 | 偏好可见且可修改，后续分析采用明确反馈优先的规则。 |
| AC-14 兴趣与认同 | PER-04 | 用户阅读或收藏一篇持某立场的文章。 | 不能仅凭此行为将该立场记录为用户认可的结论。 |
| AC-15 研究确认边界 | ANA-04、RES-01 | 默认分析提出外部查证建议，用户未确认。 | 建议可阅读，但尚未启动外部研究；已获允许的云端总结不受此限制。 |
| AC-16 多轮研究 | RES-02、RES-03、RES-04 | 用户确认目标和用量边界，研究需要多轮查证。 | Agent 能继续比较和补查，返回有来源的结论及未解问题，成果保存本地。 |
| AC-17 持续主题授权 | TRK-01、TRK-02 | 用户授权主题、频率与上限。 | 后续范围内研究无需每轮重问，同时遵守配置的用量边界。 |
| AC-18 范围扩大 | TRK-03 | 持续研究拟转向超出原授权的方向。 | 提出新的确认请求，未确认前不扩大外部研究范围。 |
| AC-19 延后与补查 | TRK-04、TRK-05 | 手机离线或长期未打开，再次打开。 | 能补查遗漏信息，显示真实最近执行时间与待执行状态；不要求云端在离线期间运行。 |
| AC-20 暂停追踪 | TRK-02 | 用户暂停已启用的主题追踪。 | 追踪进入暂停状态，不继续按原计划启动新一轮任务；在途任务细节按后续设计验证。 |
| AC-21 有意义的通知 | TRK-06 | 分别产生无重要变化、重要新发现、结论变化和需要决策的结果。 | 无重要变化时不例行通知；其余情形提供与实际结果对应的通知。 |
| AC-22 本地使用 | DAT-01、DAT-02、DAT-04、PLT-03 | 已保存资料，未登录产品账号并断开网络。 | 本地资料和已有成果仍可使用；不要求同步，也不宣称可离线调用云端模型。 |
| AC-23 备份恢复 | DAT-03 | 对包含原始资料、笔记和研究成果的数据集执行备份与恢复。 | 原始资料与成果恢复后可阅读、可使用；具体备份格式在技术设计中确定。 |
| AC-24 自有模型配置 | MOD-01、MOD-02 | 用户设置服务地址、Key、文本模型和多模态模型。 | 相应任务使用用户配置；必要内容可发送至云端，不要求 App 提供统一模型账号。 |
| AC-25 真实使用复盘 | ANA-02、TOP-04 | 用户围绕个人知识管理主题收藏、阅读并积累多条相关资料。 | 能回看有来源的观点卡片，并看到跨资料积累形成的主题综述，判断研究是否实际推进。 |

### 9.2 建议的补充验收

PER-05 及 SUG-01 至 SUG-08 应在后续设计中确认后转为正式测试：检查来源跳转、模型失败后的资料保全、中断与预算耗尽、恢复后的来源关系、生成内容标识、空资料库行为、暂停中的任务以及补查策略。它们不能被报告为已完成测试。

## 10. 后续技术设计事项

这些是实现决策，不是重新打开已经确定的产品目标。技术设计应遵守本文的本地保存、Android 优先、跨端复用和研究授权边界。

| 编号 | 待确定事项 | 不可改变的前提 |
| --- | --- | --- |
| TD-01 | 跨端框架、原生能力边界和模块复用方式。 | Android 优先，考虑 iPhone 与 Mac；不默认同时交付。 |
| TD-02 | 本地数据库、文件布局、资料索引与关联检索方案。 | 原始资料与成果本地保存，可长期积累；不擅自要求云端资料库。 |
| TD-03 | 微信公众号及博客正文提取、主要图片保存、失败回退方案。 | 以真实来源验收，不把无法读取的页面承诺为一定可完整提取。 |
| TD-04 | RSS 订阅添加、刷新、条目存储与选中后归档方式。 | 未选中条目不自动分析；RSS 拉取与外部研究权限分别处理。 |
| TD-05 | 图片与 PDF 的格式、大小、页数支持范围，以及多模态预处理与分批分析方式。 | 第一版具有实际分析能力；不预设所有模型均能直接接收所有文件。 |
| TD-06 | 模型协议、供应商兼容范围、密钥保存、长内容上下文与分析任务配置。 | 自有 Key，支持服务地址及文本／多模态模型配置；数据发送范围遵守已确认边界。 |
| TD-07 | 外部搜索服务、网页读取工具、相关凭据与 Agent 工具接口。 | 外部研究须经确认或主题授权；模型 API Key 不被假定为搜索服务凭据。 |
| TD-08 | 研究频率、用量计量单位、默认上限、超限与在途任务暂停规则。 | 有范围和用量边界，可暂停；不把未讨论的费用数字写成用户要求。 |
| TD-09 | Android 后台运行、恢复任务、补查和通知策略。 | 允许延后，打开时补查，显示真实状态，不引入必须常驻云端的前提。 |
| TD-10 | 导出与备份格式、恢复校验、密钥处理和未来跨端兼容。 | 第一期支持备份恢复但不同步；不得无依据承诺完整跨平台迁移。 |
| TD-11 | 观点卡片、主题综述、兴趣设置及研究授权的界面和具体数据结构。 | 明确区分观点卡片、主题综述、研究成果及相应授权；不以普通摘要页替代综合研究能力。 |
| TD-12 | 资料查找、去重、删除、成果更新历史和数据增长后的管理方式。 | 当前未确定具体交互、检索语法或历史保留规则，需要后续设计。 |
